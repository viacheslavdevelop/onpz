## 3. Задачи этапа

### 3.1. Подготовка окружения
- Создать `requirements.txt`: `rank_bm25`, `sentence-transformers`, `faiss-cpu` (или `chromadb`), `numpy`, `scikit-learn`.
- Проверить доступность загрузки модели эмбеддингов (нужен интернет при первом запуске `sentence-transformers`). Если офлайн — заранее скачать веса модели.
- Выбор модели эмбеддингов: текст корпуса на русском языке → предпочтительна **`sergeyzh/rubert-tiny`** (из альтернатив в ТЗ), а не `all-MiniLM-L6-v2` (она англоязычная и плохо справится с терминологией типа «ЭЛОУ», «стриппинг», «флегмовое число»). Зафиксировать выбор в README/отчёте.

### 3.2. Решение: какой набор чанков использовать
Нужно явно выбрать базовый набор для индексации (сейчас есть два):
- **V2 (`chunks_v2_by_fact.jsonl`, 206 шт.)** — рекомендуется как основной: гранулярность «один факт/одна строка таблицы» хорошо подходит под фактологические и числовые тестовые вопросы из ТЗ (где ответ — в одном фрагменте).
- **V1 (`chunks_v1_by_section.jsonl`, 45 шт.)** — крупнее, может быть полезен для процедурных вопросов, где ответ требует контекста всего раздела.
- Рекомендация: взять V2 как основной индекс для week 4–5; V1 держать как запасной вариант/для сравнения, если на процедурных вопросах V2 покажет плохой Recall.

### 3.3. Материализация тестовых запросов
В `.docx` есть 25 тестовых вопросов по 5 категориям (фактологические, процедурные, с синонимами/аббревиатурами, числовые/табличные, «ловушки»). Их нужно вынести в структурированный файл, иначе прогон и будущая оценка (неделя 7) невозможны.
- Создать `Eval/test_queries.json` (или `.csv`) с полями: `query_id`, `query_text`, `category`, `gold_chunk_ids` (пусто — заполнить вручную на неделе 7 при разметке релевантности).
- Это разовая подготовительная задача, но она логически относится к началу недели 4, т.к. без неё нельзя делать «первый прогон».

### 3.4. BM25-поиск
- Токенизация русского текста: простая регулярная разбивка + lowercase + удаление стоп-слов; опционально — стемминг/лемматизация (`pymorphy2` или `nltk.snowball.RussianStemmer`), т.к. `rank_bm25` сам токенизацию не делает.
- Построить индекс `BM25Okapi` по полю `text` чанков V2.
- Функция `bm25_search(query, top_k=5)` → список `(chunk_id, score)`.

### 3.5. Векторный индекс
- Посчитать эмбеддинги для `text` всех чанков V2 моделью `sentence-transformers`.
- Построить индекс FAISS (`IndexFlatIP` с нормализованными векторами, т.к. корпус небольшой — 206 векторов, точный поиск без приближений оправдан) либо ChromaDB — выбрать одно, не оба, для простоты (ТЗ допускает любой).
- Функция `vector_search(query, top_k=5)` → список `(chunk_id, score)`.

### 3.6. Скрипт `retrieval.py`
- Объединить BM25 и vector-поиск в одном CLI/модуле: загрузка чанков → построение (или загрузка сохранённого) индекса → функция `search(query, method="bm25"|"vector", top_k=5)`.
- Сохранять индексы на диск (`Chunks/bm25_index.pkl`, `Chunks/faiss.index` или `Chroma` persist-директорию), чтобы не пересчитывать эмбеддинги при каждом запуске.
- Предусмотреть простой режим запуска: `python retrieval.py --query "..." --method bm25 --top_k 5`.

### 3.7. Первый прогон и предварительные результаты
- Прогнать все 25 тестовых запросов через оба метода.
- Сохранить вывод в `Eval/preliminary_results.md` или `.jsonl`: для каждого запроса — топ-5 чанков от BM25 и топ-5 от вектора, визуально сравнить, где они расходятся (особенно на вопросах с аббревиатурами — ожидаемо BM25 слабее на синонимах).
- Это даст материал для недели 5 (гибрид) и недели 7 (метрики), без формального расчёта Recall/MRR — та часть осознанно отложена на неделю 7 по плану ТЗ.

## 5. Риски этапа (из таблицы рисков в ТЗ, применимо к неделе 4)
- **Векторный поиск хуже BM25 на аббревиатурах** — модель эмбеддингов может не знать «ЭЛОУ», «АВТ» как термины. Способ проверки уже на этой неделе: сравнить топ-5 BM25 и вектора на запросах категории «с синонимами и аббревиатурами» из `test_queries.json`. Если расхождение сильное — зафиксировать как входные данные для недели 5 (гибрид) и для словаря синонимов.
- Выбор версии чанков (V1 vs V2) влияет на дальнейшие метрики — явно задокументировать решение, чтобы не менять базу данных на середине работы.

## 6. Критерий готовности этапа
- `requirements.txt` и окружение воспроизводимы.
- `Eval/test_queries.json` содержит все 25 вопросов из ТЗ с категориями.
- `retrieval.py` запускается и для BM25, и для векторного поиска, возвращает топ-5 чанков с `chunk_id`, `score`, `text`.
- `Eval/preliminary_results.md` содержит прогон всех 25 запросов обоими методами — готов материал для недели 5 и 7.
