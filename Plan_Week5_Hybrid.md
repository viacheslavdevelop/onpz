## 3. Задачи этапа

### 3.1. Нормализация и объединение скоров
- BM25 (`rank_bm25.get_scores`) даёт неограниченные по диапазону скоры, вектор (FAISS `IndexFlatIP` на нормализованных эмбеддингах) — скоры в диапазоне [-1, 1]. Перед объединением нормализовать оба набора скоров (например, min-max по текущему топ-N или по всей коллекции) — иначе один сигнал будет доминировать.
- Реализовать `hybrid_score = alpha * norm(bm25_score) + (1 - alpha) * norm(vector_score)` по объединённому множеству кандидатов (топ-N от каждого метода, например top_k=20 на входе, top_k=5 на выходе).

### 3.2. Подбор веса alpha
- На имеющихся наблюдениях из `Eval/preliminary_results.md` видно расхождение: BM25 хорошо находит точный факт по леммам (F2, F3), вектор иногда "расплывается" по семантически близким, но не точным чанкам. Для объективного подбора `alpha` нужна хотя бы минимальная ручная разметка `gold_chunk_ids` — рекомендуется разметить вручную топ-кандидаты для всех 25 запросов (можно частично, начиная с категорий `factual` и `synonym_abbreviation`, где важнее всего сравнить методы).
- Перебрать несколько значений `alpha` (например, 0.3/0.5/0.7) и сравнить Recall@5 по размеченным запросам — выбрать и зафиксировать лучшее значение с обоснованием.

### 3.3. Переранжирование (опционально, если останется время)
- Простая эвристика: повысить ранг чанков, которые попали в топ-K **обоих** методов одновременно (пересечение — сильный сигнал релевантности).
- Либо реализовать RRF (Reciprocal Rank Fusion) как альтернативу взвешенному скорингу — не требует нормализации шкал, часто устойчивее.

### 3.4. Скрипт `Retrieval/hybrid_retrieval.py`
- Функция `hybrid_search(query, top_k=5, alpha=...)`, использующая уже существующие `bm25_search.py` и `vector_search.py`.
- CLI по аналогии с `retrieval.py`: `python hybrid_retrieval.py --query "..." --top_k 5`.
- Добавить `--run_all`, аналогично текущему `retrieval.py`, чтобы прогнать все 25 запросов и сохранить результат, например в `Eval/hybrid_results.md`, для сравнения с `preliminary_results.md`.

### 3.5. Сравнение с week 4
- В отчёте/README зафиксировать: на каких категориях запросов гибрид дал видимое улучшение по сравнению с чистым BM25 и чистым вектором (особенно ожидаемо — категория `synonym_abbreviation`, где по ТЗ вектор должен компенсировать слабость BM25 на аббревиатурах типа «ЭЛОУ», «АВТ», «гудрон»/«вакуумный газойль»).
